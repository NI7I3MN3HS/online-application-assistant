# 简历解析选型与接入说明

核验日期：2026-09-19。结论是对本项目约束的适配判断，不是对所有解析器的准确率排名；尚无真实用户简历集的准确率评测。

## 当前代码与使用链路

- `manifest.json`：Chrome Manifest V3 扩展，原生 HTML/CSS/JavaScript，无业务后端、无需构建。
- `src/options.js`：`profileV2` 结构，19 个标准栏目；单值栏目使用 `values`，教育、工作等重复栏目使用 `items[].values`，另外支持自定义字段、JSON 备份。
- `src/background.js`：资料与字段记忆保存在 `chrome.storage.local`；AI 接口用于网页字段理解，接收字段目录而非简历值。
- `src/content.js`：扫描标签、控件、模块、重复组与上下文，经过语义匹配、本地规则、可选 AI 与字段记忆生成填充计划；支持原生控件、日期、选择框及部分组件控件。已有智易、HotJob、猎聘、Moka、北森、牛客、智联、飞书和常见 UI 组件适配代码。
- `src/popup.js`：开始填写、资料面板、从本页学习和资料补录入口。插件不代替用户提交申请。

因此，解析器必须将文档转换为现有栏目和字段，尤其不能将多段教育/工作经历拼成一段摘要。只提取 PDF 文字并不等于完成简历解析。

## 候选比较

| 方案 | 本项目的适配情况 | 决策 |
| --- | --- | --- |
| [PDF.js](https://github.com/mozilla/pdf.js) + [Mammoth.js](https://github.com/mwilliamson/mammoth.js) | 浏览器内读取 PDF/DOCX；分别为 Apache-2.0 / BSD-2-Clause。能够随扩展分发、不需要云接口。二者是文档读取器，需要额外的简历字段映射层。 | 本次采用；自行实现中英文标题、联系方式、日期、经历分组及资料合并。 |
| [OpenResume](https://github.com/xitanggg/open-resume) | 本地浏览器方案，PDF.js 提取 + 简历规则解析；产品偏美国简历。上游采用 AGPL-3.0，直接搬入当前 MIT 项目不能继续当成单纯 MIT 代码分发。 | 作为产品与架构比较对象，不复制上游解析代码。 |
| [pyresparser](https://github.com/OmkarPathak/pyresparser) | 需要 Python、spaCy/NLTK，安装示例使用英语模型 `en_core_web_sm`。与无后端的中文网申扩展部署方式不符。 | 不作为默认依赖。 |
| [PaddleOCR](https://github.com/PaddlePaddle/PaddleOCR) | 适合中文文字识别。通常使用 Python 服务，也可以分发 ONNX 模型并在浏览器推理；OCR 输出仍需映射到简历字段。 | 本次已采用 PP-OCRv4 的 ONNX 检测/识别模型，以 ONNX Runtime Web 在扩展 Worker 中本地推理；不需要 Python 或服务端。 |
| [MinerU](https://github.com/opendatalab/MinerU) | 面向复杂文档结构提取，涉及本地模型/运行环境或远程服务，不是可直接塞进现有扩展的简历字段解析库。 | 复杂版式需求的后续候选，本次不引入服务依赖。 |

这里的“最佳”指兼顾现有隐私边界、中文字段、安装成本、维护方式和许可证的方案。无文字层 PDF 现在由本地 PaddleOCR 回退识别；极端多栏、倾斜扫描和低清图像仍需要人工核对，不承诺任意版式的完整准确率。

## 已实现

1. 在设置页选择 PDF / DOCX / TXT，或粘贴文字。文件和文本都进入独立、可终止的本地 Worker。
2. PDF.js 优先提取文字层；页面少于 12 个非空白字符时，使用受尺寸限制的离屏 Canvas 渲染，再由本地 PP-OCRv4 检测文字位置、识别文本。处理黑底白字标题，并在文字已转轮廓的页面跳过小型右上角照片，避免把人像纹理当文字。按位置重建行和右侧日期列。中文 CMap、字体、模型、字典、ONNX WASM 都随扩展分发。Mammoth 仍只读取 Word 原始文本。
3. 按中英文栏目标题、显式字段标签、日期区间和经历标题生成候选，映射到 `profileV2` 现有字段。支持基本信息、求职意向、教育、实习、工作、项目、校园经历、技能、语言、奖项、证书、自我评价等。无法可靠归类的整段内容单独提示；每组保留可查看的原文。
4. 在预览中逐字段勾选、修改；可修正整份提取原文后重新解析。推测姓名、公司或项目标题会提示核对，不补造出生日期、证件号等信息。
5. 默认补空缺、保留已有冲突值；可显式选择更新对应已有值。新经历追加到末尾；相同经历基于标识字段匹配，完全重复值跳过。
6. 点击“填入并保存资料”才写入本机。保存失败保留预览；成功后支持撤销最近一次导入。若导入后资料已被编辑或其他页面修改，拒绝直接撤销以保留修改。
7. 将字段记忆的数值索引路径升级为基于字段名称的稳定路径，并根据已有来源标签迁移旧记忆，避免浏览器存储重排或新增字段导致错位；经历出现序号优先从结构化路径读取，不要求标题包含“第 1 条”。保留备份中的未知字段、非预设选项、“至今”和仅年份的日期。
8. 修正原填表链路里原生包裹标签的优先级、跨栏目上下文污染，以及姓名/电话/学校/职位/专业课程的语义判断；导入后的重复经历可以按条填写。

原始文件不会写入本机资料库；确认的字段值会保存。原文预览只在当前页面内存中，保存/放弃后清除。此功能不使用现有 API Key，也不改变 AI 页面分析的请求内容。

## 边界与验证

- 上限：10 MB、PDF 30 页、其中最多 10 页 OCR、文本 20 万字符；OCR 渲染最长边 3600 像素且不超过 1200 万像素，检测长边约 1536 像素、识别逐行运行。DOCX ZIP 解压声明不超过 50 MB / 2000 条；PDF 总超时 180 秒，其余 45 秒，支持取消。
- 自带中英文 OCR，支持扫描型及文字转轮廓 PDF。暂不接受独立图片文件或旧版 `.doc`；密码 PDF 需先解除保护。混合 PDF 按页判断是否 OCR；同页部分文字层、部分图片的文档仍可能漏识别。
- 多栏 PDF、特殊文本框、复杂表格、无标题简历、非标准日期可能需要人工调整。不是 LLM 语义理解，不能保证所有模板都准确。解析预览是必要环节。
- `npm test` 覆盖真实编辑器字段契约、解析规则、重复经历合并、联系方式归属、文件校验、日期、字段记忆次序及填表语义回归。
- 已在隔离的 Edge 153 扩展环境验证：中文 PDF/DOCX/TXT 离线导入、保存、刷新、撤销和错误状态；1440px / 390px 界面；导入期间无外部请求、无控制台错误。
- 当前会话没有 Browser 插件技能（Browser plugin not available），因此使用捆绑 Playwright 和已安装的 Edge 执行真实扩展验证。`npm test` 共 34 项通过，新增 OCR 版式、模型输出解码、跨行教育分组、11/12 月日期、语言成绩归属等回归。
- 本地网申夹具实测 18 个字段（姓名、电话、邮箱、两段教育、工作、项目及原生选择/日期控件）全部填入预期值，未提交表单。使用测试专用 localhost 权限和临时浏览器资料目录，没有改动用户的浏览器授权。
- 已使用用户提供的单页、文字转轮廓 PDF 在隔离扩展中离线实测，识别为 19 组资料，核对姓名、联系方式、两段教育、两段实习、项目、社团、奖项、技能及 IELTS 成绩。真实文件、文字内容、照片和浏览器测试副本不进入源码或发布包；仓库只包含虚构的回归样例。尚未逐站验证所有真实招聘网站，也未做大规模文档准确率评测。
- `npm audit` 的安全公告接口在当前环境 TLS 连接失败，未得到依赖漏洞审计结论；不能将此写成“无漏洞”。

## 开发与分发

普通用户直接加载整个仓库，包含 `vendor/`，仍不需要 npm install 或构建。

维护者使用 Node.js 22.13+（或 24+）：

```sh
npm ci --ignore-scripts
npm test
npm run vendor:resume
```

固定版本：PDF.js `6.3.289`，Mammoth.js `1.12.3`，`@gutenye/ocr-models` `1.4.2`（PP-OCRv4 ONNX 模型及字典），ONNX Runtime Web `1.30.0`。OCR 检测连通区域、行裁剪和 CTC 解码由本项目实现，不分发 OpenCV 或 GutenOCR 浏览器包装层。`package-lock.json` 锁定来源；`vendor/checksums.json` 记录分发文件 SHA-256；许可证见 `vendor/THIRD_PARTY_NOTICES.md` 和对应目录。运行时不使用 CDN、不添加 host 权限。CSP 仅在本机脚本策略中加入 Chrome 支持的 `'wasm-unsafe-eval'` 以运行 ONNX；不允许 JavaScript 字符串求值或远程脚本。参见 [Chrome CSP 文档](https://developer.chrome.com/docs/extensions/reference/manifest/content-security-policy)。
